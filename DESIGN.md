# Design

## Source of truth

Status: Active. Updated: 2026-09-15. Surfaces: the existing AI Edu Day GitHub Pages home, workshop entry pages, Reading List and reading shells. Evidence reviewed: live root page, root HTML/README, GAS README and 60-minute handout, 36-slide GAS presentation, 20-slide **Oh-my-claude-code 사용기** presentation and PDF, existing reader HTML/CSS, original image manifests and passing regression tests. User references reviewed in Chrome: https://shedsgns.me/taste and https://emilkowal.ski/ui/developing-taste. Emil supplies the narrow, text-first reading model; Shed supplies spacing restraint, not its repeating decorative animation. No separate brand manual is available.

## Brand

An approachable, composed education team's working library. Quiet editorial styling: warm off-white paper, charcoal text, restrained sage links and lightly outlined material lists. The page should feel like a useful reading room rather than a promotional landing page. Trust comes from real materials, original source images and clear source/type labels. Avoid saturated orange/forest-green blocks, oversized heavy headings, tilted decorations, invented testimonials, exaggerated outcome claims and fake UI affordances.

## Product goals

Make the existing public website beautiful and usable, not a separate microsite. Visitors should understand the available material and choose a workshop or reading resource immediately. Keep the canonical Reading List under `reading-list/` and preserve all existing content URLs. Success: immediately visible static material rows, consistent two-link header, real resource actions, vertical-only page flow, preserved source bytes and passing regression/browser checks. Search/filter/count/read-status UI on catalogs is intentionally removed by the latest user design, not preserved as an invariant. Non-goals: accounts, a CMS, paid services, replacing original slide decks or creating a new hosting stack.

## Personas and jobs

Education team members and learners on laptops or phones. They need to start a guided exercise, revisit slides, download an existing PDF, or read a paper/article in Korean. Beginners need context before being dropped into a slide deck; returning learners need direct links to materials.

## Information architecture

- `/`: only a header with `Upstage Education` (home link) and `GitHub`, followed immediately by the five material rows, and below them the scrap wall from `notes.md` (hidden when the file holds nothing). No introduction, promotional copy, visible page heading, toolbar, search, filters, result count, reading status, duplicate menu or footer. Keep a visually hidden h1 and skip link for accessibility.
- `/gas-tutorial/`: workshop orientation, start-slide action, four exercise stages and actual available prompt/code/handout links.
- `/omc-intro/`: original OMC presentation context, start-slide action, the four content themes and original PDF link. Use the actual source title (Claude Code), not Codex.
- `/reading-list/`: preserve the existing URL as a reading-only view of the same material rows and two-link header, without extra controls or introduction. Individual article URLs remain reachable directly from the home catalog.
- `/reading-list/externalization-llm-agents/`: orientation and the existing beginner/deep reading documents.
- `/reading-list/forward-deployed-engineer/`: complete Korean translation of the user-supplied article: 57 body paragraphs, subtitle, 8 section headings, captions and final author bio; the supplied date is 2026-09-13. Original images precede P01 and follow P12 and P28, with no added discussion questions or editorial notes.
- `/reading-list/what-is-a-harness/`: complete Korean translation of the Earendil article, published with the author's permission: 21 body paragraphs across a dictionary definition, an introduction and six sections, keeping the original's inline links. The article's photograph was taken by Tom Frost rather than the author, and is reused on the author's representation that images are covered; the caption keeps the photographer credit and link as the original carries them, and `images/sources.json` records the permission and its date.
- `/reading-list/what-is-jev/`: a brief the team wrote itself rather than a translation, so it carries no source-translation apparatus and declares `리서치` as its format. Two comparison tables live inside `.table-scroll`, which is the only place the site uses tables; the rules are scoped to that wrapper so the legacy readers keep their own fixed-layout handling.
- Existing legacy externalization entry/deep-document URLs redirect with query/fragment preservation; old figure URLs remain byte-identical compatibility copies. The two legacy reading documents keep their words and figures, but not their old look: their embedded styles are layout only, so they inherit the site's type, colors and 760px column, draw their cards, callouts, figures and tables as square `#e6e7f5` hairline boxes, center their header like every detail page, and carry no emoji. Their article checksums track this edited text.

- Each resource folder holds its own document and assets, so that document declares its metadata in `resource:*` meta tags and the home and Reading List cards are only an index of it; a test compares the two and fails on any drift. Scraps in `notes.md` declare a `kind` the same way (`repo`, `link` or `term`, defaulting to `term`) rather than having it guessed from whether a link is present.

- Outside material is linked, never embedded. A video gets a short page of its own that says why it is worth watching and links out; an iframe or a third-party script would hand the reader to someone else's tracking on pages that currently load nothing from outside. Outward links open in a new tab with `rel="noopener noreferrer"`, and a test holds both rules for every page we author. Preserved original slide decks keep whatever they shipped with.

## Design principles

Give people a clear next action. Explain content with human titles rather than repository paths. Keep the navigation consistent while letting original articles retain their content. Static content first; enhancement must not blank the page or depend on an API. Favor a small, durable shared stylesheet over a framework.

## Visual language

Paper `#fdfdfc`, ink `#292a27`, muted `#666963`, accent `#465a50`, borders `#e3e5df`, subtle interactive surface `#f2f3ef`. Retain existing `--green` / `--rust` token names for reader compatibility, with the secondary color neutral rather than orange. Tokens belong to `reading-list/assets/reading-list.css`; portal/workshop components belong to `assets/site.css`. Use the existing system font stack without external font loading. Headings and emphasis use one 600 weight (one cut for Latin and Hangul); catalog headings 14px, tab labels 11px, summaries 12px balanced across lines, article body 18px at 1.8 line height in a centered 760px column shared with workshop pages. Catalog/header width 1080px including gutters, with enough width to read each row left to right. Each row contains category, format, title and one-sentence summary in that DOM order. Category and format sit together on a file tab ("워크숍 · 실습") that rises from the sheet's top-left edge; title and summary share the line below with the action at the right on desktop; small screens stack title, summary and action. Text wraps without truncation or horizontal scrolling. Detail pages use one centered 760px column and open the same way: a single "← 돌아가기" link (no breadcrumb), then the title alone, centered at 24px/600 (22px under 580px) with 48px above and 72px below. No description, info row or divider in the header; workshop buttons and the FDE translation's original subtitle and byline start the content below it. Contents and preparation information stay in normal document flow, not sticky or independently scrolling side panels. Material rows are square document sheets filed in a drawer: each later sheet sits in plain DOM order in front of the one above it, every sheet shares one constant z-index, and there are no rounded corners, shadows or decorative paper edges. Every sheet tucks a 16px empty bottom margin (`--sheet-tuck`) behind the next sheet at every width. Above that margin each sheet leaves a 20px strip (`--sheet-tab`) for the next sheet's tab, and an 11px padding (`--sheet-pad`) keeps text clear of both even when a row wraps. The tab has a 2px outline in one soft category color (workshop `#8faa9c`, reading `#a3a6ee`, via `--tab-line`), no bottom border, and overlaps the sheet's top line, so tab and paper read as one piece; tab text stays ink and muted. The selected sheet deepens that outline slightly (`--tab-line-strong`, 150ms): while the skim runs it is the highest sheet (`data-peak`, set by the script), otherwise the fine-pointer hovered or keyboard-focused sheet; touch never keeps a tint after a tap. The paper, its tab and its words catch the pointer where they are drawn, so a click always lands on the sheet you see. A one-line desktop sheet is about 80px tall; at 761px and wider the 40px (fine pointer) / 44px (coarse pointer) action target spills into that padding instead of setting the row height. Below 761px, rows use block layout: labels, then wrapping title and summary, then the action below. A pseudo-element owns each sheet's one solid `#e6e7f5` hairline, so overlapping sheets never draw darker seams; the outer `.learning-card` box and the real `.text-link` anchor never move, so hit areas stay fixed. Only the paper (`::before`), text and tab (`.card-content`) and the non-interactive `.action-label` travel, and the label cannot steal clicks. Reader link boxes and workshop buttons are square too. Touch and coarse pointers keep the same stacked look with no motion. Scraps are not documents: they sit on a wall below the drawer as equal squares of warmer paper (`#f7f6f2`, `#e3e1da` hairline, no tab, no radius), holding a term, one muted line and any links, which open in a new tab. Pointing at one lifts it 10px off the wall with a faint shadow (240ms up, a softer 420ms settle back), the way you pick up a sticky note; nothing tilts, ripples or moves on its own, and reduced motion keeps it flat. Preserve original article figures/photos, uncropped and unfiltered.

Fingertip skim: `assets/drawer.js` follows the mouse over the drawer with an exact critically damped spring (about 130ms to 90%, no overshoot at any frame rate) and raises each sheet by a Gaussian of its distance from the pointer (up to 12px, `--sheet-lift`), so a soft bulge glides along the stack instead of switching card by card. Before moving, the script measures how much room each sheet has between its own tab or edge and the text of the sheet behind it, and never lets it rise past that room minus 4px. Each sheet's row starts at its tab, so pointing at a tab raises that tab's own sheet; the bulge depends only on pointer height, never on the element under the pointer, so it cannot feed back on itself. It writes `--sheet-y` per sheet each frame, follows scrolling, measures again when rows are added or the layout resizes, stops and removes its inline values at rest, and resets on `pagehide` and window blur. Mouse and pen skim; touch does not. Keyboard `:focus-visible` on a sheet's link moves the bulge to that sheet while the pointer is outside the drawer; the pointer takes over while it is inside. It runs only for `(hover: hover) and (pointer: fine)` without `prefers-reduced-motion`; without JavaScript the drawer stays still and every link works. No CSS transitions on the sheet layers, no scale, tilt, keyframe animation or restacking. With the script, a click anywhere on a sheet opens its document like its link (modifier and middle clicks open a new tab; a click that ends a text selection does nothing). Opening a document uses a same-site view transition: the header holds still (`site-header`), the old page fades out in 140ms, the new page fades in over 200ms after 60ms, and the clicked title (named `doc-title` by the script at `pageswap`) glides into the destination `.workshop-title`/`.reader-title` over 320ms; `pagereveal` glides it back on return. Leaving or returning to a page whose header is scrolled out of view, or clicking a link to the current page, skips the transition so nothing flies in. Shift-click is left to text selection, Cmd/Ctrl-click is forwarded to the link, and middle-click opens a new tab. Reduced motion sets `navigation:none`; browsers without cross-document view transitions open pages instantly. Links and buttons keep their 150ms color feedback. The catalog focus ring is drawn around the travelling action label, not the stationary link box, so the next sheet does not hide it at rest or under keyboard focus; if the pointer lifts the next sheet, its edge may briefly touch the ring.

## Components

Shared two-link header, skip link, visually hidden catalog heading, uniform four-field document sheet and right-aligned action. Workshop action buttons, one back link per detail page and essential exercise links remain. Reader: static article title, byline/source attribution, body text and original inline figures. Do not render progress, font-size controls, completion state, breadcrumbs, outer or embedded contents navigation, or a “next reading” footer. Footer and catalogue-only controls are removed, not merely hidden. All actions are real links/buttons; no placeholder controls.

## Accessibility

Target WCAG AA: semantic landmarks, one primary heading, meaningful link names, explicit input labels, visible focus and keyboard-operable controls. Skip links move focus into main. Maintain at least 4.5:1 contrast for normal UI text despite the softer palette. Resource actions retain visible keyboard focus and meaningful accessible names. Catalog titles are plain headings rather than a second duplicate link; repeated action text includes the material title in its accessible name. No motion required to understand content; respect reduced motion. Mobile target controls at least 44px where practical. Do not lock scroll, force scroll positions, capture arrow keys or suppress normal keyboard/link navigation. Vertical flow describes layout, not an input restriction.

## Responsive behavior

Desktop: compact document strips tuck 16px behind each other at every width; fields read left-to-right with the action at the right. Skimming moves only paper, text and labels: stacking order never changes and no row's hit area moves. Tablet/phone: allow natural field wrapping rather than sideways scrolling, with the same DOM order. The two header links stay on a single row; no hamburger or extra navigation. Detail pages remain a single vertical reading flow. Check at 1440, 768, 390 and 320 CSS pixels. Original wide tables and code wrap within the reader; avoid horizontal page or nested-panel scrolling. Images retain aspect ratio.

## Interaction states

All static rows and links work with JavaScript disabled. GitHub discovery may append unknown root-level collections/PPTX in the same row format but never replaces static resources. No search or filter controls, counts or read-state labels are rendered on catalogs. API errors/timeouts leave known content usable. Article pages have no reader settings, progress meter, completion state, contents navigation or browser-storage dependency.

## Content voice

Korean-first, direct, welcoming and specific. English for familiar technical names and understated visual labels. State real formats and grounded durations: GAS handout says 60 minutes; OMC has 20 slides. No invented completion promises. Distinguish original content from summaries. Do not add discussion questions or editorial filler to the FDE page. Follow better-writing for newly written Korean; do not rewrite preserved source articles.

## Implementation constraints

Static HTML/CSS/JavaScript; no new dependencies, font CDN, tracking, framework or hosting migration. Relative internal paths must work locally and under `/eduteam-ai-edu-day/`. Preserve user untracked files and original slide/article/image/PDF bytes. Existing regression tests lock source content. Before delivery run Node tests, JS syntax, internal-link/fragment checks, Korean copy checks and Chrome desktop/mobile/no-JS/offline/keyboard checks; inspect screenshots. Publish only to the existing main/root GitHub Pages configuration after user approval and passing verification; check previous deployment before a single push.

### Fingertip skim refinement

1. A single-sheet CSS hover (8px rise, 4px lean) fixed the old stacking pop but felt almost the same as before, and a CSS neighbour wave still switched card by card.
2. The user compared three local prototypes (continuous bulge, titles-only peek, 3D flip-through) and chose the continuous bulge, with square sheets and no decorative edges or shadows. Category and format then moved from inline tags to a file tab on each sheet, like the index tab of a paper folder.
3. `assets/drawer.js` drives the bulge with a spring; CSS keeps only resting geometry, the shared `--sheet-y` translate and reduced-motion/print resets.
4. Verify in Chrome: continuous in-between heights during a slow move, 0 restacks, paper and print in sync, at most about 4px per frame, text clearance during a 60fps sweep, keyboard focus, touch and reduced motion, 1440/768/390/320 layouts.
5. Release only after user approval: bump the asset version in the entry shells, push once after the previous Pages build finishes, then verify production.
